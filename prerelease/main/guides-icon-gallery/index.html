Icon gallery

Icon gallery

Every icon this site’s UI bundle actually ships, so you never have to guess a group/name string and find out only after a card renders with a blank header slot.

The set below is fixed by whichever @inditextech/docouture-ui-bundle version this site depends on — a normal site cannot add to it. The icons come from Inditex’s proprietary internal design-system mirror; the fetch/build tooling that vendors them (src/img/icons.yml, just icons-fetch/icons-build) only runs inside the docouture monorepo itself, against an internal asset host. Need one that isn’t here? Open a request against the docouture repository — there’s no way to add it from a site that just depends on the published bundle.

Two places an icon reference is read, two different rules

  • nav_modules[].icon (see Adding a module) is resolved by a Handlebars helper at page-render time, with full access to the icon sprite — any icon in this gallery works there, both sections below.

  • [card,icon="group/name"] (see Custom AsciiDoc components) is resolved by the Asciidoctor extension itself at build time, which has no access to the sprite at all — it can only emit a pre-generated CSS class. Only the icons in the first section below have one. Reference one from the second section instead, and nothing errors — the card just renders with an empty icon slot, silently.

Usable in [card,icon=]

Every icon here has a generated CSS mask, so it’s guaranteed to actually render in a card’s header. Copy the group/name string as-is.
