About

About

docouture is a documentation platform: an Antora content pipeline, a UI bundle with its own design tokens, and the docouture CLI that ties them together — scaffolding, serving, building and publishing a site without hand-wiring an Antora playbook from scratch.

It ships three things a documentation site actually needs:

  • Consistent themed UI — @inditextech/docouture-ui-bundle, a themed fork of antora-ui-default carrying dark/light mode, a version switcher, full-text search, and a set of authoring blocks ([tabs], [cards], [accordion], [feature-tabs], [cta]) with no plain AsciiDoc equivalent — see UI Bundle and Custom AsciiDoc components.

  • Power-up AsciiDoc and Antora extensions — a module switcher, a site footer, a full-text search index, llms.txt/llms-full.txt generation, Kroki diagram rendering and Shiki syntax highlighting, wired up by default — see Integrations.

  • Tooling and scaffolding — docouture new scaffolds a site into an existing git repository; docouture dev/build/publish run it; docouture doctor checks it’s healthy; docouture version/upgrade/eject/teardown cover the rest — see CLI.

Who it’s for

Mainly InditexTech teams documenting an InditexTech Open Source project — this site you’re reading is itself one, scaffolded the same way Quickstart describes. Nothing about the CLI, the Antora pipeline or the UI bundle underneath restricts that audience — see the FAQ for the full licence breakdown.

What it isn’t

docouture is not a general-purpose static site generator — it’s opinionated about being an Antora site built with this specific UI bundle. Antora’s own content model (components, versions, modules, resource IDs) is the model docouture builds on, not one it hides; see Architecture and Glossary for the vocabulary.
