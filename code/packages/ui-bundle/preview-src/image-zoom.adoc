= Image Zoom (GH-197)
:page-layout: default
:description: Click-to-zoom fullscreen overlay for `[role=zoom-in]` images and Kroki diagrams — image-zoom-dialog.hbs, image-zoom.css, 14-image-zoom.ts.
:!example-caption:

This page reviews the click-to-zoom overlay (GH-197): the cursor/hover affordance
for a mouse (resize this page's viewport, or check dev tools' device toolbar for
the touch badge instead — `@media (hover: none)`, image-zoom.css), the dialog
itself, and the diagram bleed fix (diagram.css) side by side with an
un-zoomable image for comparison.

== Plain images

.A small photo, marked `role=zoom-in` — click it. The frame does not stretch to fill any bled width (doc.css's own `.imageblock`/`.content` split, unchanged by GH-197).
image::photo-small.jpg[A small photo,role=zoom-in]

.A large photo past the +25% cap, marked `role=zoom-in` — clamped down to the budget same as any other image, but still opens the overlay at its own real size.
image::photo-large.gif[A large photo,role=zoom-in]

.The same large photo, WITHOUT `role=zoom-in` — no cursor, no hover tint, no badge, nothing opens on click. For comparison only.
image::photo-large.gif[A large photo, not zoomable]

== Diagrams

Kroki isn't wired into this preview harness (no `kroki-enabled` attribute, no
live Kroki service — kroki.js's own header) — real Mermaid/PlantUML markup
here would just show literal source text, not a diagram. The two fixtures
below are hand-written passthrough HTML in EXACTLY the shape kroki.js now
emits (GH-197's two-div split — diagram.css's own header), so the dialog and
the bleed fix are both reviewable without a live Kroki instance.

.A small inline SVG "diagram", marked `zoom-in` — same "no oversized empty frame" check as the small photo above, on the diagram side of the split.
++++

  <div class="docouture-diagram__content">

      <text x="50" y="50" text-anchor="middle" font-size="12">Start</text>

  </div>
</div>
