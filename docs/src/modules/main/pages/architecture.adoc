= Architecture

docouture is three cooperating pieces, each replaceable on its own.

== The content pipeline: Antora

Antora aggregates https://asciidoc.org[AsciiDoc] content from one or more git
repositories/refs into a single site, based on a *playbook* (`antora-playbook.yml`) and
one *component descriptor* (`antora.yml`) per documentation component. docouture
doesn't replace Antora's model — it generates a playbook and descriptor that already
point at the right things, and layers extensions on top. See
https://docs.antora.org/antora/latest/[Antora's own documentation] for the model
itself, and xref:main:antora-playbook-configuration.adoc[]/
xref:main:antora-yml-configuration.adoc[] for what this site's own copies of those two
files say.

== The UI: a themed Antora UI bundle

`@inditextech/docouture-ui-bundle` is a themed fork of
https://gitlab.com/antora/antora-ui-default[antora-ui-default]: Handlebars layouts and
partials, CSS built on the IOP Design System's tokens, and browser scripts for theme
switching, search, tabs, accordions and the on-page table of contents. Antora reads it
as a plain zip (`ui.bundle.url` in the playbook) — nothing about it is
docouture-specific from Antora's point of view. See xref:main:ui-bundle.adoc[].

== The extensions: two different seams

Two packages hook two different parts of the pipeline, registered under two different
playbook keys:

* `@inditextech/docouture-antora-extensions` (`antora.extensions`) hooks Antora's own
  site-generation pipeline — the module switcher, the site footer, the search index,
  `llms.txt` generation, the https://kroki.io[Kroki]/https://shiki.style[Shiki] prewarm
  steps, legacy URL redirects, and the `/latest/` alias.
* `@inditextech/docouture-asciidoc-extensions` (`asciidoc.extensions`) hooks the
  https://asciidoctor.org[Asciidoctor] processor itself — `[tabs]`, `[cards]`,
  `[accordion]`, `[feature-tabs]`, `[cta]`, the `label:`/`mono:` macros, table/video
  sizing attributes, and the Kroki/Shiki block implementations.

Listing either package under the other's key makes Antora log a warning and skip it —
see xref:main:antora-playbook-configuration.adoc[].

== The CLI: scaffolding, not a build tool

`docouture` (`@inditextech/docouture-cli`) doesn't build anything itself — `docouture
build`/`dev` are thin wrappers around Antora, and `docouture publish` resolves a
publish driver package (`@inditextech/docouture-publish-<target>`) from the site's own
`node_modules`. What the CLI actually owns is scaffolding (`new`), version bookkeeping
(`version`), diagnostics (`doctor`), and re-syncing generated files
(`upgrade`/`eject`/`teardown`) — see xref:main:cli-api.adoc[].

== How a build actually runs

. `docouture build` (or `dev`) shells out to the site's own `npm run build`, which runs
  `antora --fetch antora-playbook.yml`.
. Antora aggregates content from `content.sources[]`, applies `asciidoc.extensions` to
  every page, then runs `antora.extensions` over the resulting site model.
. The UI bundle renders the result through its Handlebars layouts.
. `docouture publish <target>` (a separate step) pushes whatever is at `output.dir`
  (default `build/site`) using that target's driver package.
