Icon gallery

Icon gallery

Every icon this site’s UI bundle actually ships, so you never have to guess a name and find out only after a card renders with a blank header slot.

The set below is fixed by whichever @inditextech/docouture-ui-bundle version this site depends on — a normal site cannot add to it at request time, since the sprite is baked into the published package. The icons themselves come from Lucide (ISC licensed, public npm) — a name here is the same name lucide.dev/icons/<name> uses, so browsing that catalogue is a legitimate way to find a candidate before checking whether it’s already vendored below. Need one that isn’t? Open a request against the docouture repository — vendoring a new Lucide icon is one line in packages/ui-bundle/src/img/icons.yml plus a UI bundle release, but a site consuming the published package can’t do that itself.

Two places an icon reference is read, two different rules

  • nav_modules[].icon (see Adding a module) is resolved by a Handlebars helper at page-render time, with full access to the icon sprite — any icon in this gallery works there, both sections below.

  • [card,icon="name"] (see Custom AsciiDoc components) is resolved by the Asciidoctor extension itself at build time, which has no access to the sprite at all — it can only emit a pre-generated CSS class. Only the icons in the first section below have one. Reference one from the second section instead, and nothing errors — the card just renders with an empty icon slot, silently.

Usable in [card,icon=]

Every icon here has a generated CSS mask, so it’s guaranteed to actually render in a card’s header. Copy the name as-is.
