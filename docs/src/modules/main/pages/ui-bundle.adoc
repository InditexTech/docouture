= UI Bundle

`@inditextech/docouture-ui-bundle` — a themed fork of
https://gitlab.com/antora/antora-ui-default[antora-ui-default], read by
https://antora.org[Antora] as a plain zip via `ui.bundle.url`. What follows is what a
site actually gets from it, beyond styling.

== Theme: dark / light

A theme toggle persists the choice (localStorage), applied before first paint so
there's no flash of the wrong theme. `product_logo_dark` (see
xref:main:setup-the-product-logo.adoc[]) is swapped in automatically under dark mode.

== Navigation

* *Module switcher* — appears once a component has more than one entry in
  `nav_modules`; see xref:main:adding-a-module.adoc[].
* *Nav tree* — renders each module's own `nav.adoc`.
* *Breadcrumbs* — derived from the navigation tree's ancestors of the current page.
* *Pagination* — previous/next footer links, on by default site-wide via
  `page-pagination: '@'` (see xref:main:antora-playbook-configuration.adoc[]); a page
  can opt out with `:!page-pagination:`.
* *"Edit this page"* — links to the content source's edit URL, inferred for known git
  hosts.
* *Header repo link* — reads `site.keys.repo_url`, or falls back to the content
  source's own git remote if that key isn't set.

== Table of contents

An "on this page" scrollspy TOC tracks the current section as you scroll; a page can
suppress it with `:page-role: -toc`. Heading anchors are clickable (`sectanchors`).

== Search

A search dialog reads the full-text search index
`@inditextech/docouture-antora-extensions` builds at build time (see
xref:main:features.adoc[]) — without that extension registered, the dialog renders
but has nothing to search. Recent searches persist locally.

== Version switcher

A version dropdown renders once a component has more than one version — see
xref:main:versioning-modes.adoc[]. A single-version component (the common case before
a first release) renders a plain version indicator instead of a dropdown.

== 404 page

Antora's own generated 404 page has no component/module context at all — no side
menu, no version tag, no footer. `@inditextech/docouture-antora-extensions` composes a
real one instead, using `not_found_module` (xref:main:antora-yml-configuration.adoc[])
so every partial that reads page context renders exactly as it would on a real page.

== Copy-to-clipboard

Every code block gets a copy button, regardless of whether it has a language set.

== Configuration surface

Everything a site actually configures on the UI bundle, in one place:

[cols="1,2"]
|===
|Key |Effect

|`site.keys.product_logo`/`product_logo_dark` |xref:main:setup-the-product-logo.adoc[]
|`site.keys.favicon` |xref:main:setup-a-favicon.adoc[]
|`site.keys.repo_url` |Header toolbar repo link, overriding the git-remote fallback
|`ui.bundle.url`/`snapshot` |Which bundle zip, and whether to cache it
|`ui.supplemental_files` |Overlay directory for the logo/favicon files above
|`ui.default_layout` |Layout for pages with no `page-layout` attribute (default `default`)
|`ui.output_dir` |Where UI assets land inside the site (default `_`)
|===
